# M1.1 — Contract Validation Tooling

**Status:** Tooling and CI scaffold committed; first GitHub Actions run is the execution proof.  
**Scope:** Machine-readable contracts and repository-relative documentation links.

## What is installed in the repository

- scripts/validate-contracts.mjs — one local/CI entry point.
- .github/workflows/contracts.yml — pull-request, push and manual contract validation.
- .redocly.yaml — explicit Redocly lint configuration.
- contracts/fixtures/v1/*.valid.json — positive fixtures.
- contracts/fixtures/v1/*.invalid.json — negative fixtures.

## Pinned tooling

| Tool | Pinned version | Purpose |
|---|---:|---|
| Node.js | 24 (CI runtime) | Execute validation runner |
| @redocly/cli | 2.72.1 | OpenAPI 3.x and AsyncAPI 3.x parsing/linting |
| ajv-cli | 5.0.0 | Compile and execute JSON Schema Draft 2020-12 positive/negative fixtures |

Versions are pinned in the script, not floated through latest. Update them through a reviewed dependency/tooling change.

## Local execution

Requirements: Node.js 24 and npm/npx available on PATH.

~~~sh
node scripts/validate-contracts.mjs
~~~

The first execution downloads the exact pinned CLI packages through npm. Redocly telemetry is disabled for this validation process.

## Checks performed by the runner

1. Required OpenAPI and AsyncAPI source files exist.
2. Repository-relative Markdown links and local image paths resolve.
3. Every JSON Schema has one parseable positive and one parseable negative fixture.
4. Redocly lints the OpenAPI v1 document.
5. Redocly lints the AsyncAPI v1 document.
6. Ajv compiles each Draft 2020-12 schema.
7. Ajv accepts the positive fixture for each schema.
8. Ajv rejects the negative fixture for each schema.

A failed tool invocation is a failed validation; the runner does not convert a failure into a warning or success.

## Current limitations

- The Markdown checker checks repository-relative target existence, not heading-anchor correctness or reference-style links.
- Positive/negative fixtures are intentionally minimal contract smoke tests, not exhaustive property-based tests.
- Lint findings must be fixed at the owning source; do not suppress rules merely to obtain a green workflow.
- This workflow does not compile Rust, build UI packages, run Windows sandbox tests or certify runtime security.
- A successful workflow run is required before this M1.1 stage is marked validated.

## Acceptance criteria

- A GitHub Actions run on main completes successfully.
- A deliberately malformed OpenAPI, AsyncAPI, JSON Schema fixture or local Markdown link causes the job to fail.
- A corrected contract and fixture make the job pass.
- The workflow runs on relevant pull requests before merge.
