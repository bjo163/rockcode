# M1.3 — Provider-neutral completion contract and OpenAI-compatible gateway

**Status:** Implementation submitted for CI review

## Scope

This slice creates a canonical model request/response boundary in the Rust kernel and one OpenAI-compatible HTTP adapter. It does not implement function/tool calling, session management, context compaction, or a complete coding-agent turn loop.

## Canonical kernel contract

- Messages use canonical system, user, assistant, and tool roles.
- Provider-specific wire formats are created below the kernel boundary.
- Completion requests support optional temperature and output-token limits.
- Completion responses carry assistant text and the provider finish reason.

## OpenAI-compatible provider

Environment configuration:

- ROCKCODE_PROVIDER_BASE_URL — provider API base ending in /v1 or equivalent, for example https://api.openai.com/v1.
- ROCKCODE_PROVIDER_API_KEY — secret bearer token; never log or persist it in UI state.
- ROCKCODE_MODEL_ID — model identifier accepted by the selected provider.

The adapter sends POST to {base_url}/chat/completions, applies a 90-second request timeout, and reads only the assistant text and finish reason. HTTP failures and malformed responses return the generic kernel gateway error so credentials and provider response bodies are not copied into logs or public errors.

HTTPS is enabled with rustls and platform-native certificate roots. HTTP is accepted only for loopback provider endpoints; non-loopback providers must use HTTPS so API keys are not sent in plaintext. The URL parser is pinned at 2.5.9 to include the RUSTSEC-2026-0592 fix.

## Explicit non-goals

- Tool/function call normalization and execution are not implemented.
- This adapter does not execute shell commands or modify workspaces.
- It does not store provider credentials; environment variables are a bootstrap path. Desktop integration must move secrets to the OS credential store.
- No API endpoint or UI yet exposes this provider in the product.

## CI acceptance

- Rust formatting and Clippy on Ubuntu and Windows.
- Unit tests for configuration validation, canonical-to-provider request mapping and response parsing.
- Existing runtime and architecture tests remain green.
