# M1.5 — Safe Read-Only Workspace Tools

**Status:** Implementation submitted for CI review

## Scope

This milestone adds only two workspace capabilities behind the existing \`ToolInvoker\` interface:

- \`workspace.read_file\` — read one UTF-8 text file.
- \`workspace.list_files\` — list immediate children of a workspace directory.

It does not expose writes, patches, shell commands, Git mutations, or arbitrary host paths.

## Workspace boundary

- The selected workspace root is canonicalized once at construction and must already exist as a directory.
- Tool paths are relative to that root. Absolute paths, parent traversal, prefixes, and unsupported path components are rejected.
- Every resolved target is canonicalized and must remain inside the canonical workspace root.
- File symlinks pointing outside the workspace are rejected. Directory listings omit symlinks instead of following them.
- Read operations use the canonical target path and a bounded stream read.

## Sensitive-path filtering

Common credential locations and files are blocked from direct reads and omitted from directory listings, including:

- \`.git\`, \`.ssh\`, \`.aws\`, \`.gnupg\`, and \`.config\` paths;
- \`.env\` and \`.env.*\`;
- \`.npmrc\`, \`.pypirc\`, and \`.netrc\`;
- names beginning with \`credentials\` or \`secrets\`;
- common private-key/certificate extensions (\`.pem\`, \`.key\`, \`.p12\`, \`.pfx\`, \`.jks\`, \`.keystore\`).

This is a conservative path-based denylist, not a general-purpose secret detector. It does not guarantee that arbitrary source/configuration files contain no secrets.

## Resource bounds

- Maximum read-file size: 512 KiB.
- Maximum directory output: 200 immediate entries; response reports whether the listing was truncated.
- No recursive traversal.
- Blocking filesystem calls are dispatched through Tokio's blocking thread pool.

## Integration boundary

- \`WorkspaceToolInvoker\` implements the kernel's \`ToolInvoker\` trait and can be composed with the M1.4 runtime.
- Tool definitions are exported separately so the runtime can advertise only the read-only capabilities.
- The local \`agentd\` server and Desktop UI do not yet construct this invoker or expose a coding session endpoint.
- This tool adapter is not an OS sandbox. The runtime must still require explicit policy \`Allow\`; future write/shell tools require separate sandbox enforcement.

## CI acceptance

- Rust fmt, Clippy, workspace tests, architecture tests and strict cargo-deny on Ubuntu and Windows.
- Tests cover normal reads, traversal/absolute-path rejection, common secret-path filtering, symlink escape, size limits, directory output bounds and unknown tools.
