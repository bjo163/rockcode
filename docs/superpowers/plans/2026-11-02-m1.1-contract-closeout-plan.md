# M1.1 Contract Validation Closeout — Implementation Plan

**Design:** [2026-11-02-m1.1-contract-closeout-design.md](../specs/2026-11-02-m1.1-contract-closeout-design.md)
**Date:** 2026-11-02
**Design owner approval:** given in conversation ("tulis plan manual" after spec review)

## Ordering rationale

The order is not A→B→C→D as the design lists the units. It is:

**transport → findings-are-failures → config → contract edits → coverage → self-check → docs**

because:

1. Without T2 the validator cannot run at all on the owner's Windows machine, so
   every later edit to 23 operations would be blind and verifiable only through CI.
2. T3 deliberately makes the gate **red** on the 31 existing findings. That red is
   the evidence for acceptance criterion "a malformed contract causes the job to
   fail" ([M1.1 §Acceptance criteria](../../specs/m0/M1.1-contract-validation.md)) —
   observed on a real defect, not manufactured. Fixing A/B afterwards turns it green
   with the same gate.
3. Coverage (T6) and the mutation self-check (T7) come last because they assert on a
   contract shape that must exist first.

Every task's verification runs from a clean checkout (`git archive`), per the standing
rule that local green ≠ the pushed commit builds.

### T2 — Transport: make the runner executable on Windows
[scripts/validate-contracts.mjs:18-48](../../../scripts/validate-contracts.mjs#L18).

- Resolve `npx-cli.js` from `process.execPath`; documented fallback search.
- **Windows only.** `spawnSync(process.execPath, [npxCli, "--yes", ...pkg, ...args], { shell: false })`.
  POSIX keeps calling `npx` directly, which is **unchanged** from the committed
  behaviour. Deviation from the first draft of this task: changing a platform that
  every CI run has already proven working, on an unverified path guess, is risk for
  no benefit. Probe **P3 is therefore closed by removal** — there is no Linux path
  assumption left to test.
- Switch `stdio: "inherit"` → captured `stdout`/`stderr` with `encoding: "utf8"`
  (T3 needs to read them). Echo the captured output so local runs stay readable.
- Keep `--package` pins exactly (2.72.1 / 5.0.0 / 3.0.1).
- If `npx-cli.js` is not found on Windows: **fail**, printing every searched path.
  Never skip, and never fall back to a shell.

i.e. zero `spawnSync ... EINVAL` lines, and 17 checks report a real validator verdict.

## Stop conditions

- Do **not** mark M1.1 validated from a green run alone — design §1.1 is exactly that
  failure mode.
- Do **not** suppress a Redocly rule to reach green (D2).
- Do **not** commit a broken `contracts/**` to prove CI can go red (D4).
- Do **not** push, open a PR, or touch branch protection without an explicit ask.
- Do **not** extend scope into POC-01, contract freeze, or M0 closure.

## Effort and risk

- T2 is the only change with unknown blast radius: it is the first time the runner
  executes on Windows. Expect surprises in captured-output handling, not in logic.
- T5 is the largest file diff (23 operations) but is mechanical once the table is set.
- Tightening `ErrorResponse.error.code` is only safe because no runtime exists yet
  (design §3.1 A3). That is a one-time window; it closes at the M1 freeze.
